fix: declare artifact content types explicitly, not via mimetypes

CI failed on windows-latest + Python 3.10 (the other four jobs passed).
Cause: _serve_file guessed with mimetypes, whose strict table has no
`.md` until 3.11. On Windows it reads no system mime database, so
guess_type("note.md") returned None, my fallback emitted
application/octet-stream, and the assertion `startswith("text/")`
failed. Ubuntu 3.10 passed only because /etc/mime.types supplies the
mapping -- same interpreter, different answer.

That is the wrong property for a response header. Replaced the guess
with an explicit _ARTIFACT_TYPES map covering what Elixir actually
writes to artifacts/ (fetched pages are .md, screenshots .png, captures
.pdf), defaulting to application/octet-stream. The Content-Disposition:
attachment header is unchanged and still on every response, which is
what stops an HTML or SVG in artifacts/ being rendered in our origin
against the Studio token.

The test now asserts the exact Content-Type rather than a prefix, so it
checks determinism instead of whichever mapping the host happens to
have, plus an unknown extension falling through to octet-stream.

60 tests pass locally, pyflakes clean.
