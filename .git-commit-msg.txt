fix: say "not on PATH" when an installed tier cannot be found

`elixir doctor` reported `cua` and `apps` as `off  pip install ...` on a
machine where both were installed. pip falls back to the user Scripts
directory when it cannot write site-packages, and that directory is not
on PATH by default, so shutil.which() missed launchers sitting right
there -- and the hint told people to reinstall software they already had.

_probe_missing checks importlib.metadata first: absent keeps the install
hint, present names the directory to add. That directory comes from
sysconfig's nt_user/posix_user scheme. site.USER_BASE looked like the
answer but is version-less on Windows, so joining it with "Scripts"
yields ...\Roaming\Python\Scripts when the real one is
...\Roaming\Python\Python313\Scripts -- I shipped that wrong path once
and the live probe caught it. The test now asserts the suggested path
comes from sysconfig, so the substitution cannot come back.
