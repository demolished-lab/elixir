security: refuse cross-site GETs, declare real artifact content types

Two faults found by driving the live Studio rather than the fixtures.

1. do_GET only checked Host. Origin was enforced on POST alone, so a
   foreign page's GET was served -- 200, just unreadable, because we
   never send Access-Control-Allow-Origin. Not sending ACAO does stop the
   response being parsed, but the request still executed and the
   token-bearing bootstrap page was still fetched cross-site. Checking
   Origin on reads as well closes that for good: `GET /` and every
   tokened route now answer 403 to `Origin: https://evil.example`.
   Native clients send no Origin, so curl, the CLI and the Studio page
   itself are unaffected.

2. _serve_file declared every artifact except a PDF as
   `text/markdown`, so a screenshot went out as markdown. Guess the type
   with mimetypes and fall back to application/octet-stream. The
   `Content-Disposition: attachment` header stays on every response --
   that is what keeps an HTML or SVG dropped into artifacts/ from being
   rendered in our origin against the Studio token.

Regression tests: cross-site GET refused on both the bootstrap page and
a tokened route; PNG sent as image/png, .md as text/*, .html never
inline. 60 tests pass, pyflakes clean. Verified against a live server:
GET / cross-site 403, /shot cross-site 403, /file f=act_check.png 200
image/png attachment with intact PNG magic bytes.
